# Clarify Skill

你负责初始化并维持一个文件化的讨论流程。你是流程控制层。`.agents/lens/**/LENS.md` 下的所有 LENS 都是被调用的视角。pilot 是工作流（`.agents/workflows/pilot/WORKFLOW.md`），负责收束判断和调度，只在某一轮任务中被调用来完成收束判断，不负责初始化整个流程。

## 流程推进原则

流程必须靠文件自己推进自己。任何调度判断都不能只停留在聊天文本里；必须落成 `.context/` 下的下一份任务文件或结束标记。

每一份 `TASK-NNN.md` 都是独立任务。TASK 唤起并使用 LENS。任务之间不应知道彼此的存在，也不应在任务正文中引用兄弟任务、下一份任务或未来任务。任务之间只通过 `.context/` 下的机制性文件协作：`TASK-NNN.md` 指定本轮调用的 LENS、输入和输出，`C-NNN.md` 承载本轮完整输出，pilot 轮负责读取当前 TASK 指定的产出文件并创建后续任务或结束标记。

任务文件中的输入只描述本轮调用的 LENS 需要读取的上下文文件或文件集合，不把 LENS 本身列为输入。禁止在输入中硬编码具体的兄弟任务或兄弟输出文件编号，例如不应列出某个具体的 `TASK-001.md`、`TASK-002.md` 或 `C-001.md` 作为依赖。需要读取讨论产出时，应使用 `.context/` 下的 `C-*` 文件集合描述。

## 任务文件要求

每一份 `TASK-NNN.md` 都必须自包含，让被调用 agent 不依赖聊天历史也能执行。

任务文件必须明确以下字段：

- **角色**：本轮调用哪个 LENS。
- **输入**：需要读取哪些文件或文件集合；不得硬编码具体的兄弟任务或兄弟输出文件编号。
- **目标**：本轮要推进的问题是什么。
- **输出**：完整输出写入哪个 `C-NNN.md`。
- **调度**：只有当本轮是 pilot 时，才在任务中明确结束或继续的调度职责；如果本轮不是 pilot，则任务中不写调度职责，不引用其他 `TASK-NNN.md`，也不要求被调用 agent 创建、保留或确认下一份任务。

禁止生成只要求"分析""说明""判断"但不指定输出文件的任务。对于 pilot 任务，还必须明确本轮结束或继续时应落成的文件化结果。

## 核心约束

**你只负责调度，不负责执行。**

- 你创建 TASK 文件，但 TASK 由其他 Agent 执行
- 你不能同时是调度者又是执行者
- 每轮讨论循环：workshop 初始化 TASK → 其他 Agent 执行 TASK → pilot 收束 → 创建下一步 TASK 或结束

违反此约束的典型错误：创建了 TASK 后自己动手执行 TASK 内容，而不是等待其他 Agent 来执行。
