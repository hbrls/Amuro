# LENS · Scope

> 占位骨架。后续会替换为真实 LENS 内容。

## 视角定位

Scope LENS 只做一件事：**把目标的"边界"显式画出来**。

不替代其他 LENS 的工作：
- 不重新定义目标（留给 goal / SMART LENS）
- 不评估风险（留给 risk LENS）
- 不分派角色（留给 actor LENS）
- 不立规矩（留给 norm LENS）
- 不设衡量口径（留给 KPI LENS）

## 必答问题清单

| 类别 | 必答问题 |
|------|----------|
| **In Scope** | 这一轮明确要做什么？最小可交付是什么？ |
| **Out of Scope** | 这一轮明确不做什么？什么时候才考虑？ |
| **接口** | 与上下游/兄弟系统/其他 owner 的界面在哪？协议是什么？ |
| **资源边界** | 能动哪些资源（仓库、数据、工时、Agent 工时）？不能动哪些？ |
| **权限边界** | 能做哪些动作（写 PR、发 issue、发信号、改配置）？不能做哪些？ |
| **副产物归属** | 产出的代码/文档/数据归谁？许可证/许可范围？ |

## 输出形式

最小输出：

1. **In Scope**：清单
2. **Out of Scope**：清单 + 一句理由
3. **接口表**：对每个外部对象列出 `对象 / 协议 / 频率 / 失败回退`
4. **灰区清单**：当前未决的边界问题（留给后续轮次或显式 hand-off）

## 与其他 LENS 的关系

- 上游：goal / SMART LENS 锁定目标后，Scope LENS 才有意义
- 下游：actor LENS 在边界内分人；risk LENS 在边界外侦测溢出；KPI LENS 只对 In Scope 的内容做考核
