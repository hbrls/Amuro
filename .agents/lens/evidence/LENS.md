# Evidence LENS

> updated_by: Codex - GPT-5
> updated_at: 2026-06-13 00:00:00

## 目标

Evidence LENS 的目标不是直接判断根因，而是先把问题转化为可采集、可复核、可晋级的证据结构。

适用场景：

- 用户描述仍停留在“不可用”“拿不到”“异常”“失败”等模糊表述。
- 需要区分失败形态，而不是直接归因。
- 需要建立兼容矩阵、样本池、证据等级或补证清单。
- 根因可能跨系统接口、厂商层、SDK、业务封装、异步桥接、缓存状态等多个层级。

## 输出

使用本 LENS 时，至少应产出：

1. 失败形态分类表。
2. 每类失败形态的判定标准、典型观察、区分点和最小证据。
3. 设备、系统、App、调用链路、运行结果、来源可信度的证据采集清单。
4. 兼容矩阵或样本表字段定义。
5. L0 到 L4 证据等级规则。
6. 证据不足时的状态标记规则。
7. 样本从线索池晋级到矩阵、再晋级到根因候选的门槛。
8. 当前不能做出的结论清单。

## 证据等级

| 等级 | 定义 | 允许结论 |
| --- | --- | --- |
| L0 线索 | 只有用户描述、评论、转述或无版本信息记录 | 只能写“待确认”，不能进入根因判断 |
| L1 基础样本 | 有基础对象信息，但缺少完整日志或调用链路 | 可记录为待补证样本，不能写确定失败形态 |
| L2 可判定失败形态 | 有对象信息、版本、调用路径、返回值或异常日志 | 可写入失败形态和异常状态 |
| L3 可支撑根因候选 | 在 L2 基础上有对照组、复现记录或调用链路边界证据 | 可写根因域候选及置信度 |
| L4 可支撑根因结论 | 有稳定复现、对照组、底层日志或最小复现实验 | 可写根因结论，但仍需标注证据边界 |

## 常用失败形态

| 失败形态 | 判定标准 | 最小证据 |
| --- | --- | --- |
| 正常 | 调用成功，结果符合对照基线 | 对象信息、版本、调用路径、返回数量、关键结果抽样 |
| 空结果 | 调用完成且无异常，但返回长度为 0 | 原始返回值、底层无异常证据、调用日志 |
| 不完整 | 返回非空，但缺少应出现的数据 | 返回数量、期望清单、缺失项、对照来源 |
| 抛异常 | 链路抛出系统、SDK 或业务异常 | 异常类型、堆栈、触发入口、版本信息 |
| 权限拒绝 | 日志或异常明确指向权限、可见性或策略限制 | 权限声明、授权状态、异常或拒绝日志 |
| 截断 | 返回存在稳定数量上限或边界缺失 | 多次采样、完整对照、缺失模式 |
| 封装层异常 | 底层未确认失败，封装层返回错误、空值或吞异常 | 封装层入参出参、错误码、底层调用证据 |
| 环境不可测 | 样本、日志或访问条件不足 | 来源记录、缺失项、下一步补证动作 |

## 采集清单

设备与系统：

- 品牌、型号、设备指纹、系统版本、补丁版本、样本来源。

App 与配置：

- App 版本、build、渠道、targetSdk、manifest 或能力声明、权限状态。

调用链路：

- 入口、实际 API 或 wrapper、参数、flags、过滤规则、是否分页、是否缓存、是否桥接。

运行结果：

- 原始返回值、数量、关键样本、异常堆栈、错误码、耗时、调用开始和结束日志。

对照与复现：

- 正常对照、同条件多次采样、清缓存或清权限前后对比、二次调用结果。

来源可信度：

- 来源人或系统、采集时间、是否可复现、是否有原始日志或截图、是否二次转述。

## 晋级规则

样本进入矩阵至少需要达到 L2：

- 对象身份明确。
- 版本信息明确。
- 调用路径明确。
- 运行结果明确。
- 失败形态可判定。
- 证据可追溯。

样本进入根因候选至少需要达到 L3：

- 有正常对照或异常对照。
- 有调用链路边界证据。
- 有配置、权限、版本或环境变量对照。
- 有稳定复现或多次采样。

## 禁止事项

- 不得把用户描述直接写成根因。
- 不得把空结果自动等同于权限拒绝。
- 不得把单个样本泛化为全部型号、全部版本或全部环境。
- 不得在 L3 之前写确定根因。
- 不得把二次转述、截图、评论当作 L2 失败形态证据。
- 不得混入当前 Vision 边界之外的问题线。
