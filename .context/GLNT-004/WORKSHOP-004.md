## 6. 接手方式

### 6.1 如何继续扩展

如有新发现的头部 Android 设备指纹 / device intelligence 厂商，按 `Android-Compute-Dimensions.md` §3 编号约定模式：

1. 厂商 LENS 反推独立 C 文件（按 C-003 §6 模板 F-1 ~ F-11 字段填充）
2. 反推维度按 C-003 §5.2 编号约定建立新前缀（与既有 S / M / SE / T / X / SI / U / C / DX / I / B / DV / FZ / U2 / YJ / JD / TD / WY / BD / GT 不冲突）
3. 归位分歧按 C-003 Q2 双归位模式显式决断
4. 资料覆盖按"≥ 4"门槛（v2.0 整合后重校）
5. 由 goal LENS 整合入主清单，由 pilot LENS 收束判断

### 6.2 如何使用 v2.0 主清单

- **维度查询**：按 10 个分组定位，按编号前缀定位厂商来源
- **新增维度**：先看是否已存在既有编号（避免重复）；按归位分组决定落入哪个组
- **双归位条目**：在主清单分组顶部有"双归位引用"标注；不重复增加总条数
- **未决问题**：242 条未决问题分布在各厂商 LENS F-10；作为后续"全量调研阶段外"深度补充入口（按厂商对接 / 反编译 SO 库 / 控制台登录 / demo app 触发）

### 6.3 校准后门槛使用

- 任何新厂商 LENS 反推：反推维度 ≥ 25 / 归位分歧 ≤ 15 / 未决问题 ≤ 30 / 资料覆盖 ≥ 4
- pilot 收束判断：按此门槛实测；如发现仍需校准，按 Android-Compute-Dimensions.md §0 校准机制"由 pilot 收束按厂商实际数据 ± 5 调整"

### 6.4 不变量

- C-003 §5.1 首版种子（S-001 ~ S-010）保留；M-001 ~ M-018 保留
- Android-Compute-Dimensions.md §0 校准机制保留（由 pilot 按数据调整）
- 编号约定不与既有 20 套前缀冲突
- 主清单 v2.0 不重做（仅在新增厂商 LENS 时增量纳入）
