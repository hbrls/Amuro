# `$WebClick` 口径说明

> updated_by: Codex - GPT-5
> updated_at: 2026-07-13 20:23:30

## 1. 事件概览

`$WebClick` 是神策 Web JS SDK 全埋点中的 **Web 元素点击**事件，用于自动记录用户在 Web 页面上点击的 DOM 元素，主要服务于点击图和 Web 点击行为分析。

它描述“用户点击了哪个 Web 元素”，不是页面浏览、视区停留或业务转化结果。SDK 自动附带元素身份、内容、类型、选择器和页面上下文；关键业务语义仍可能需要手工事件补充。

### 运行环境与触发口径

**普通 Web 页面：**页面接入神策 Web JS SDK，并启用全埋点或点击图相关能力后，用户点击符合采集规则的 DOM 元素时自动上报 `$WebClick`。

**H5 页面：**移动浏览器中的 H5 页面按同一 DOM 点击口径采集。

**App 内嵌 H5：**WebView 内的 H5 若接入 Web JS SDK 并开启点击采集，点击上报为 `$WebClick`，不是 App 原生 `$AppClick`。

**App 原生端：**iOS、Android、HarmonyOS App SDK 不使用 `$WebClick`；原生控件点击使用 `$AppClick`。

**小程序端：**小程序点击依赖宿主组件和小程序 SDK 规则，不使用 Web DOM、CSS selector 或 `$WebClick`。

神策 Web 全埋点包含 Web 页面浏览、Web 元素点击、Web 视区停留三类事件，分别对应 `$pageview`、`$WebClick`、`$WebStay` 的核心语义位置。

### 触发与配置边界

`$WebClick` 的自动采集需要满足以下条件：Web JS SDK 已初始化并开启点击采集；用户点击符合规则的 DOM 元素；当前页面和元素未被排除；相关字段符合隐私和内容采集配置。

SDK 根据元素类型、内容、选择器和页面信息构造事件。页面级或元素级排除规则会使对应点击不自动上报；合规场景也可能要求用户同意后才启用采集，或关闭元素内容、链接和选择器等敏感字段。

自动采集无需为每个按钮手写 `track()`，覆盖范围广，但受 DOM 结构、隐私策略和字段稳定性约束。

## 2. 关键属性

| 属性名 | 显示名 | 类型 | 含义 |
| --- | --- | --- | --- |
| `$element_id` | 元素 ID | 字符串 | 被点击元素的 `id` |
| `$element_content` | 元素内容 | 字符串 | 被点击元素的文本或可提取内容 |
| `$element_type` | 元素类型 | 字符串 | 被点击元素的 HTML 标签或类型 |
| `$element_selector` | 元素选择器 | 字符串 | 被点击元素的 CSS selector 路径 |
| `$element_path` | 元素路径 | 字符串 | 元素在页面结构中的路径信息 |
| `$element_position` | 元素位置 | 字符串或数值 | 元素在同类或列表中的位置，具体取值依赖 SDK 规则 |
| `$url_path` | 页面路径 | 字符串 | 点击发生时的页面路径 |
| `$url` | 页面 URL | 字符串 | 点击发生时的完整页面地址，是否采集依赖公共预置属性口径 |
| `$title` | 页面标题 | 字符串 | 点击发生时的页面标题 |
| `$latest_referrer` / `$referrer` | 来源页面 | 字符串 | 点击发生前的来源信息，字段名依赖 Web SDK 版本与配置 |

`$element_selector` 是点击图定位元素的关键字段，但对 DOM 层级变化敏感。页面改版、组件库升级和动态列表重排都可能改变 selector。

稳定维护的 `$element_id` 通常比纯 selector 更适合作为长期分析维度。动态生成或重复 ID 仍需单独验证。

`$element_content` 可用于分析按钮文案和链接文字，但会受多语言、动态内容、脱敏及隐私配置影响，可能为空或被过滤。

`$element_position` 可辅助分析列表中第几个元素被点击；商品 ID、价格、类目、活动 ID 等业务字段通常不在自动元素属性中，需要手工事件或业务属性补充。

## 3. 神策口径下的场景解释

`$WebClick` 记录符合采集规则的 DOM 点击。页面上发生了业务动作，不代表一定会产生该事件；元素被排除、SDK 未启用或事件发送失败都可能造成缺失。

### 场景一：点击普通按钮

**Web 页面：**用户在营销落地页点击“立即购买”按钮。SDK 捕获 DOM 点击并上报 `$WebClick`，记录按钮文本、元素类型、selector 和页面路径等信息。

该事件可统计 CTA 点击次数和点击人数，并作为页面浏览到后续下单之间的交互节点；下单结果仍应由业务转化事件确认。

### 场景二：点击导航菜单

**Web 页面：**用户点击页面顶部“价格”导航。SDK 上报 `$WebClick`，`$element_content` 可为“价格”，`$element_type` 可能是 `a` 或导航容器内实际被点击的元素。

该场景可分析不同导航入口的使用分布，辅助调整信息架构。

### 场景三：点击列表中的第 N 个商品

**Web 页面：**用户点击商品列表第 3 个卡片。SDK 可记录 selector、元素内容和 `$element_position`。

这些属性可分析列表位置点击分布；若需要商品 ID、价格、类目等维度，通常还需业务属性或手工埋点。

### 场景四：点击动态渲染组件

**Web 页面：**React 或 Vue 组件动态渲染按钮，页面版本变化时 DOM 层级随之改变。SDK 仍可采集 `$WebClick`，但 `$element_selector` 可能发生变化。

点击图适合观察当前版本分布；长期指标应优先依赖稳定业务标识，不能只依赖 selector。

### 场景五：点击被排除的元素

**Web 页面：**输入框、隐私区域或安全操作被配置为不采集。用户点击后，SDK 不生成 `$WebClick`，或保留事件但不采集敏感内容，具体取决于项目规则。

分析“某区域无人点击”前，必须先确认页面、元素及内容字段是否被排除。

### 场景六：在 App 内嵌 H5 点击按钮

**App 内嵌 H5：**WebView 打开 H5 活动页，用户点击按钮。只要 H5 初始化 Web JS SDK 并开启点击采集，点击以 `$WebClick` 上报，而不是 `$AppClick`。

原生点击和 H5 点击属于不同端事件。跨端漏斗需要保留事件来源，不能直接混为同一点击口径。

## 4. 与相近事件的边界

### 与 `$pageview`

`$pageview` 是 Web 页面级入口事件，描述用户打开或浏览了哪个页面；`$WebClick` 是元素级交互事件，描述用户在页面中点击了哪个元素。

一个 `$pageview` 页面内可以产生多条 `$WebClick`。有页面浏览不代表发生点击；有点击通常应存在页面浏览上下文，但 SPA、缓存和延迟上报可能使关联需要结合 URL、会话和用户标识验证。

### 与 `$WebStay`

`$WebStay` 的核心对象是浏览器视区，描述页面区域是否形成有效停留；`$WebClick` 的核心对象是 DOM 元素，描述具体点击。

用户看到区域但没有点击，可能有 `$WebStay` 而没有 `$WebClick`；用户快速点击，也可能有 `$WebClick` 而没有达到 `$WebStay` 的有效停留阈值。两者结合可分析“有效触达后是否点击”。

### 与 `$AppClick`

两者语义上都表示点击，但元素模型和字段体系不同。

**iOS：**`$AppClick` 依赖 iOS 原生控件和页面模型，不使用 DOM 或 CSS selector。

**Android：**`$AppClick` 依赖 Android 原生 View 和页面模型，不使用 DOM 或 CSS selector。

**HarmonyOS：**`$AppClick` 依赖 HarmonyOS 原生组件和页面模型，不使用 DOM 或 CSS selector。

**Web 页面：**`$WebClick` 依赖 DOM、HTML 标签、元素文本和 `$element_selector`。App 内嵌 H5 的点击通常仍属于 `$WebClick`。

跨端点击次数不能直接合并，除非下游先定义统一的业务点击并完成字段映射。

### 与小程序点击事件

小程序点击依赖小程序组件和宿主 SDK 规则，不等同于 Web DOM 点击。`$WebClick` 的 selector、路径和元素内容不能直接套用到小程序组件。

两者都可用于交互分析，但字段体系和可采集内容不同。`Index.md` 没有单独列出 `$MPClick`，因此这里只说明边界。

### 与手工业务点击事件

`$WebClick` 自动采集，覆盖广，但业务语义较弱。业务通过 `track('ClickButton')`、`track('SubmitForm')` 等方式上报的事件覆盖较窄，却可稳定携带商品 ID、按钮业务名、订单状态等字段。

自动点击适合发现行为和热力分析；关键转化应使用手工业务事件，或用稳定业务属性补充，避免仅凭 DOM 点击推断业务完成。

### 与 `AppCrashed`

`AppCrashed` 是 App 原生端崩溃事件；`$WebClick` 是 Web 端元素点击事件，两者没有直接配对关系。

App WebView 中点击 H5 按钮后发生崩溃时，`$WebClick` 是否已经上报取决于点击回调、网络发送、缓存策略和崩溃时机。神策 `$WebClick` 文档没有给出与 App 崩溃的直接关系，不能下确定结论。

## 5. 核验结论与适用边界

### 当前结论

`$WebClick` 是 Web DOM 元素的自动点击事件，是点击图和元素点击热力分析的基础数据。它最适合回答“用户点击了哪个 Web 元素”，不适合单独回答“页面是否被浏览”“区域是否被有效看到”或“业务转化是否完成”。

长期使用时应优先选择稳定元素 ID 或业务标识，并把 selector、元素内容和页面上下文的版本变化纳入数据治理。

### 指标处理口径

| 指标 | 是否依赖 `$WebClick` | 理由 |
| --- | --- | --- |
| 按钮点击次数 / 点击人数 | 强依赖 | 直接记录元素点击行为 |
| 点击图 / 热力点击分析 | 强依赖 | Web 点击图的基础事件 |
| 页面转化漏斗 | 中依赖 | 可作为浏览和转化之间的节点，结果仍需业务事件确认 |
| 导航使用分析 | 强依赖 | 可统计导航元素点击分布 |
| 商品卡片点击 | 中依赖 | 可记录元素和位置，业务字段可能不足 |
| 页面浏览 PV | 不依赖 | 应使用 `$pageview` |
| 页面区域触达率 | 不直接依赖 | 应使用 `$WebStay` |
| 异常分析 | 弱依赖 | 可辅助定位异常前最后一次 Web 点击，不能替代异常事件 |

### 待核验事项

- Web 端是否实际接入神策 Web JS SDK，SDK 版本及全埋点 / 点击图开关。
- 哪些页面、元素或元素类型被排除自动点击采集。
- 是否允许采集元素内容、链接、selector 等敏感或结构性字段。
- CLKLOG / CDP 是否对 `$WebClick` 二次封装、改名或增加业务属性。
- 10 组关键字段在生产数据中的完整性、类型和版本差异。
- `$element_id` 是否稳定且唯一，`$element_selector` 在页面改版后是否仍可关联。
- 多语言、动态文本和脱敏规则对 `$element_content` 的影响。
- SPA 路由变化后 `$url_path`、`$url`、`$title` 是否归属正确。
- App WebView 与普通浏览器是否使用相同初始化和发送策略。
- 关键转化是否已有手工业务事件承接商品、活动、订单等语义。

### 关键假设与适用限制

- 当前口径假设页面接入神策 Web JS SDK，并启用 Web 全埋点或点击采集；生产体系二次封装或改名后只能以本文作为基准对照。
- 页面或元素排除规则会造成预期内缺失，不能直接解释为用户没有点击。
- 合规或隐私配置可能过滤 `$element_content`、链接和 selector。
- `$element_selector` 对 DOM 结构敏感，不适合作为不经治理的长期唯一标识。
- `$element_content` 会受多语言、动态内容和隐私脱敏影响。
- 自动属性通常不足以表达商品、优惠券、活动和订单等关键业务语义。
- SPA 路由上报异常可能使点击归属到错误页面。
- App WebView 的初始化、缓存和网络发送策略可能与普通浏览器不同。
- `$WebClick` 与 `$AppClick`、小程序点击事件字段体系不同，不能直接跨端合并。
- 当前尚未验证生产数据中的事件存在性、字段完整性、脱敏、路由归属和发送可靠性。
