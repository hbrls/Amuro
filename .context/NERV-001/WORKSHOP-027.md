# Noi 技术产品调研

> updated_by: Qoder - Claude
> updated_at: 2026-07-30 19:05:00
> evidence_window: 2026-07-30；GitHub 仓库 lencx/Noi main 分支快照；最新 Release v1.1.0（2026-01-15 发布）；官网 noib.app

## 交付结论

1. **符合"主体工作在 PC"要求（有前提）**：Noi 是基于 Electron 的桌面应用，应用本体、多窗口管理、会话隔离、提示词管理、内置终端、历史与设置数据均在本机运行和存储（官方宣称 local-first：history / prompts / settings stay on-device）。但其核心使用价值依赖**嵌入第三方 AI 网页服务**（ChatGPT、Claude、Gemini、DeepSeek、Grok、Perplexity 等），这些服务本身在外部云端——属于"本地壳 + 外部第三方 SaaS 内容"的形态，产品自身**没有官方云端后端**，也没有需要调研的自建网关。
2. **符合 Windows / macOS 工作机要求**：v1.1.0 官方发布完整的 Windows 产物（`Noi-1.1.0.Setup.exe`、`Noi.msi`，另有 Squirrel 自动更新用的 `.nupkg` + `RELEASES`）和 macOS 产物（arm64 / x64 两种架构的 `.dmg` 与 `.zip`）；官网 noib.app 提供对应下载入口。Linux 产物同时存在但与本调研无关。
3. **产品本质**：一款面向 AI 重度使用者的"AI 聚合桌面浏览器 / 工作台"——把多个 AI 聊天网页收进一个桌面应用，提供多窗口并行、账号会话隔离、提示词库、内置终端（nsh）以及 `noi` CLI（可被 Claude Code / Codex / Gemini CLI 等编码代理调用来控制 Noi）。
4. **维护状态活跃但曾长期断档**：项目 2023-10 创建，2024-03 发布 v0.4.0 后停更近两年，2026-01 以 v1.0.0 大改版回归（v1.0.0 → v1.1.0 间隔 9 天），最近推送 2026-02-04，Issue 活跃至 2026-07（调研当月）。社区规模可观（约 8965 stars / 703 forks / 224 open issues），但为单一作者（lencx）驱动。
5. **重要风险——主程序未开源、无许可证**：main 分支只有 configs / extensions / locales / prompts / resources / website 等配置与官网内容，**不含应用主程序源码**；仓库无 LICENSE（API 返回 license: null）；社区提问 "Build the app locally" 无人回答。企业引入需按"免费闭源桌面软件"评估，而非开源软件。
6. **升级兼容性风险**：0.4.0 → 1.x 大改版存在用户数据迁移问题（多个 Issue 反馈自定义链接丢失、旧配置文件被移除），跨大版本升级需预期配置重建成本。

## 产品调研

### 产品定位与目标用户

- **一句话定位**："Less chaos. More flow."——把多个 AI 聊天服务聚合进一个可定制桌面浏览器的 AI 工作台。
- **目标用户**：同时使用多个 AI 网页服务（ChatGPT、Claude、Gemini、DeepSeek、Grok、Perplexity、Qwen 等，见仓库 topics）的个人效率用户与开发者；v1.1.0 起新增"被 AI 编码代理控制"场景（Claude Code / Codex / Gemini CLI 用户）。
- **免费 + 打赏模式**：无付费版证据；作者通过 Buy Me a Coffee / 微信打赏获得支持。

### 核心流程

用户下载安装桌面应用 → 打开 Noi，在侧边栏选择 AI 服务（内嵌对应网页并登录自己的账号）→ 多窗口并行使用多个 AI、会话相互隔离 → 使用提示词库组织/复用 prompt → （可选）用内置终端 nsh 执行本地命令，或从外部编码代理通过 `noi` CLI 控制 Noi。

### 功能地图与边界

- **当前能力（v1.x，官方 README/Release）**：交互优先的浏览工作流、多窗口管理、会话隔离、local-first 数据（历史/提示词/设置本机存储）、AI 提示词管理、内置终端、`noi` CLI、多主题。
- **v0.x 曾有、v1.x 状态存疑的能力**：Noi Ask（一次提问广播到多个 AI）在 2026 年 Issue 中仍被高频提及（#451、#450、#428），推导 v1.x 仍保留该能力但对部分服务（NotebookLM、ChatGPT Team 版）兼容性不稳；浏览器扩展机制 v0.x 基于 Electron 的 Chrome 扩展 API 子集实现，v1.x 后 extensions 目录仅剩说明文件，实际扩展能力状态**未决**。
- **边界**：不自带模型、不提供 API key 直连模式（社区有此需求的 Idea 讨论，未见落地）；AI 能力完全依赖用户在内嵌网页中登录的第三方账号。

## 技术架构调研

### 系统全貌与运行形态

- **运行形态**：单一 Electron 桌面应用（证据：extensions/README 直接引用 electronjs 扩展 API 文档；Windows 发布物含 Squirrel.Windows 特征文件 `.nupkg` + `RELEASES`；安装包体积 120–175MB 符合 Electron 特征；仓库主语言 TypeScript）。
- **系统边界**：全部产品逻辑在本机应用内；应用内嵌多个第三方 AI 网页（Chromium webview/BrowserView，推导）；无自建服务端。
- **主要组件（推导 + 官方描述）**：主窗口/多窗口管理器、AI 服务内嵌视图（按服务隔离会话）、提示词管理模块、内置终端 nsh、`noi` CLI、配置中心（`noi_user` 用户配置目录，Issue #435 提及）。

### 主要组件与核心链路

1. **多 AI 并行使用链路**：用户在侧边栏选择 AI 服务 → 应用加载该服务网页（独立会话分区，Cookie 隔离）→ 用户以自己的账号交互 → 历史/设置写入本机。跨网络边界仅发生在"内嵌网页 ↔ 第三方 AI 云服务"之间，属第三方 SaaS 通信，不经过 Noi 任何服务器。
2. **提示词/Noi Ask 链路**：本地提示词库 → 注入到内嵌 AI 网页输入框（一键发送/广播）→ 由于依赖对第三方页面 DOM 的适配，第三方改版即失效——这解释了反馈主题 1 的高频出现（推导，与 Issue 证据一致）。
3. **CLI 控制链路（v1.1.0 新增）**：外部工具（Claude Code 等）调用本机 `noi` 命令 → 控制 Noi 应用行为。为本机进程间通信，具体机制**未决**。

### 主要依赖

- 运行时自包含（Electron 捆绑 Chromium/Node），无需用户预装运行时。
- 强依赖网络与第三方 AI 服务账号；离线状态下仅本地功能（提示词管理、终端）可用（推导）。
- 仓库 `configs/noi.conf.json`（28.5KB 服务清单/配置）存在被应用远程拉取作为配置源的先例（v0.x 时代 `noi.mode.*.json` 即远程配置，Issue #432 佐证其变迁）；若 v1.x 沿用，则 GitHub 可达性影响服务列表更新（推导，未决）。

### 接口形态

- 用户界面：桌面 GUI（多窗口）。
- 命令行：`noi` CLI（v1.1.0 引入，命令集"持续扩充中"，官方未公布完整命令清单）。
- 扩展：v0.x 支持 Electron 实现的 Chrome 扩展 API 子集；v1.x 实际支持状态未决。
- 无对外 HTTP API 服务的证据。

### 持久化方式

- 官方明确 local-first：历史、提示词、设置全部本机存储。
- 用户配置目录名为 `noi_user`（Issue #435 提及），精确路径与格式**未决**（未经安装验证）。
- 无云同步/云备份能力的证据（Discussions 中"跨设备导出设置"仍靠手工拷贝）。

### 通信方式

- 应用 ↔ 第三方 AI 服务：内嵌网页的标准 HTTPS 通信，由各 AI 服务自身协议决定。
- 应用内部：Electron 主进程/渲染进程 IPC（推导，Electron 标准形态）。
- 自动更新：Windows 走 Squirrel（`RELEASES` 文件下载 1.7 万次，说明存量用户在用自动更新通道）；macOS 提供 `.zip` 符合 Electron autoUpdater 特征（推导）。
- 无自建长连接/服务端通道。

### 部署形态

#### 工作机安装（Windows / macOS）

- **Windows 安装方式与入口**：
  - `Noi-1.1.0.Setup.exe`（Squirrel 安装器，通常 per-user 安装、无需管理员权限——推导）；
  - `Noi.msi`（适合企业分发场景）；
  - 自动更新通过 Squirrel（`.nupkg` + `RELEASES`）。
- **macOS 安装方式与入口**：
  - `Noi-1.1.0-arm64.dmg`（Apple Silicon）/ `Noi-1.1.0-x64.dmg`（Intel），拖拽安装；
  - 官网 noib.app 按芯片架构分列下载链接。
- **依赖、权限与网络要求**：无前置运行时依赖；需要网络访问第三方 AI 服务；有用户询问"为何请求扫描本地网络设备"（Discussion 样本），具体权限行为未决；macOS 签名/公证状态**未决**——官方文档站（noib.app/docs）目前内容为空，未提供安装 FAQ，若未公证则首次打开需用户手动放行（推导）。
- **卸载方式**：Windows 经"应用和功能"标准卸载；macOS 删除 .app 并清理 `noi_user` 配置目录（目录位置未决）。

#### 主体功能运行位置

- **主体功能在 PC 本地**：应用逻辑、窗口/会话管理、提示词库、终端、数据存储全部本机。**判定：符合要求。**
- 前提须知：产品价值依赖外部第三方 AI SaaS（用户自有账号），这不是 Noi 的云端组件，但意味着核心使用场景必须联网、且受第三方服务条款约束。

#### 云端网关（如存在）

- 产品自身**无云端网关**。仅存在两类轻量外部依赖，简单提及：GitHub Releases 承担安装包与自动更新分发；GitHub 仓库 configs 可能承担服务清单配置下发（推导）。均不展开调研。
