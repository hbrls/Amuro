## 二、是否应该结束讨论？

**判断：讨论应结束。**

理由如下：

### 2.1 已产出可交付、可执行的结论

C-003 不是概念性讨论，而是一份**可直接用于实现的架构文档**：

- **写入协议明确**：5 类产出物 → 4 种写入方式（APPEND / OVERWRITE / UPSERT / APPEND+gated）→ 3 个目标文件
- **人机分工清晰**：每个字段归属到人/LLM/提议-确认三个层级，Exit Conditions 设为绝对不可写区
- **触发时机具体**：每次交互结束 / 用户确认后 / 阶段变化时，逐产出物给出理由
- **兼容路径可行**：3 阶段迁移，4 种旧 lead 兼容场景已列出处理方式

这是一份"拿给工程师就能开工"的产出，讨论的增量价值已达到递减点。

### 2.2 剩余未覆盖项是执行层面问题，非讨论问题

| 剩余缺口 | 性质 | 为什么不需要继续讨论 |
|---------|------|-------------------|
| 知识读取/检索机制 | 设计层面 | C-003 已明确"写入格式决定检索模式"，读取应在写入实现并验证后设计。先讨论读取无锚点 |
| MVP yes/no 显式边界 | 管理层面 | 可从 C-003 的五类产出中直接提取——MVP = 产出 A/B/C 的写入闭环；非 MVP = 产出 D/E（需人确认）、跨 lead 检索。不需要新一轮讨论 |
| 有用性判断标准 | 实验层面 | 基线 = 不使用分析区时追单循环的效果。指标 = token 消耗差、蒸馏命中间隔、异议遗漏率。这些应在实现后通过实测确定，不靠讨论 |
| 跨 lead 知识调用 | 高级特性 | C-001/C-002/C-003 一致同意先做单 lead 闭环。等单 lead 链路跑通后再开新讨论 |

### 2.3 已形成共识基座

三个 lens 在以下要点上完全对齐：

1. 这不是"要不要做 RAG"——是 Agent 的长期记忆基础设施
2. 写入先于读取——先让数据沉下来，再设计怎么取
3. 单 lead 闭环先于跨 lead——MVP 原则
4. Amuro 是工作台不是自动驾驶——消息发送和阶段变更的门始终在人手里

继续讨论是重新确认已共识的点，不会带来增量。

## 三、当前结论（供后续执行参考）

### 3.1 核心设计决策

写入闭环 = 每次追单循环产出 5 类内容，按以下路径写入 lead 文件：

| 产出 | 目标文件 | 写入方式 | 是否需要人确认 |
|------|---------|---------|:----------:|
| 蒸馏结论 | `analysis.md` #Client Distillation | APPEND | 否 |
| 信心评估 | `Index.md` ##Confidence + ##Confidence History | OVERWRITE + APPEND | 否 |
| 异议地图 | `analysis.md` #Objection Map | UPSERT | 否 |
| FUP 提案 | `followups.md` FUP-00N | APPEND (status: proposed) | **是** |
| 阶段变化 | `Index.md` / `analysis.md` | 人确认后 LLM 记日志 | **是** |

### 3.2 文件增量

```
leads/{lead_id}/
├── Index.md          ← 现有，新增: ##Confidence, ##Confidence History, ##Stage History
├── analysis.md       ← 新文件，#Client Distillation, #Stakeholder Map, #Opportunity Hypotheses, #Objection Map, #Cycle Log
└── followups.md      ← 现有，新增: status=proposed
```

### 3.3 MVP 边界

**MVP 内**：
- 五类产出的写入闭环（全部，因为产出 A/B/C 自动写入和 D/E 人确认写入是一体流程）
- 新 lead 从创建起带 `analysis.md` 骨架
- 旧 lead 首次追单时按需创建 `analysis.md`

**MVP 外**：
- 知识读取/检索（向量检索、语义匹配）
- 跨 lead 知识交叉调用
- write-back 冲突的分布式解决方案
- 知识版本回滚机制

### 3.4 有用性验证方向（待实现后实测，非本轮讨论继续）

- **对照基线**：无 analysis.md 时追单循环的蒸馏质量（token 消耗、关键信息遗漏率）
- **核心指标**：引入写入闭环后，第二次追单是否比第一次更快、更准（蒸馏命中率、信心趋势一致性）
- **退化警戒**：蒸馏追加出现大量重复内容、analysis.md 膨胀导致加载成本超过收益
