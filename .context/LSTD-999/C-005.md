# C-005 · Goal 视角澄清

> LENS：goal
> 范围：`.context/LSTD-1234/Index.md` 中 WORKSHOP-003 KPI 口径锁定议题
> 视角：goal（目标是否清晰、是否可被驱动、是否存在未决假设）

## 1. 重述当前目标

Amuro 是**总项目**，负责管理并**主动推进**所有并行子项目（LLM wiki、设备指纹算法、flowable→cf workflow 迁移等）。WORKSHOP-001 已确立三原则（观测先于行动 / 方法库不锁定 / 每轮推进必须收束）与四条硬约束（写权限默认零 / 决策权不可让渡 / 信息流入最小化 / 默认异步非阻塞）。WORKSHOP-002 已闭环方法库枚举：6 个 MVP 方法 M1~M6、15 对关系矩阵、1 个暂定主方法 M2、3 个越界方法 V1~V3、9 个收束信号占位。

**WORKSHOP-003 本轮目标**：围绕 WORKSHOP-002 §8 收束信号占位，为 M1~M6 锁定**可执行 KPI 口径 / 初始目标 / 观察窗口**，为 V1~V3 锁定**越界审计口径**，使「推进项目」从方法清单进入**可衡量、可观察、可复盘**的执行口径。

约束继承 + 本轮新增：KPI 必须绑定可观测收束信号（不接受 Amuro 自行判定完成）、必须区分 MVP 推进指标与越界审计指标、初值必须保守（试运行后可轮换或调参）、不反向修改 WORKSHOP-002 已收束成果。

## 2. 识别核心问题

把"目标"拆成可被 KPI 锁定的子问题，**真正困难的不在数值本身，而在三件事的并存**：

1. **KPI 的"信号纯度"问题**：WORKSHOP-002 §8 的收束信号占位本质是"事件计数"。一旦把事件计数直接当 KPI，会把"系统噪声"和"真实推进"混在一起。例如 PR 创建数既包含 owner 主动推进、也包含越界方法触发、还包含机器提交。如果 M4 KPI 直接 = PR 创建数，就会同时奖励"越界"和"灌水"。
2. **MVP 方法 vs 越界方法的"度量不对称"问题**：M1~M6 是**推进指标**（越大越好，方向正向），V1~V3 是**审计指标**（越界本身不应被鼓励，但越界信息必须有可观察口径）。两套指标用同一套数值方向会失败——若 V 指标也用"计数+阈值"，会变相鼓励越界以"凑指标"。
3. **保守初值与"启动期观察"的时间窗问题**：本轮明确 KPI 初值必须保守、可在试运行后调参。但"保守"在不同方法上的含义不同：M2 owner 行动率 0.3 是按"月级活跃 owner / 计划内 owner"还是按"周级事件密度"？M4 PR 接受率 0.5 是按"所有 PR"还是按"非破坏性补丁子类"？观察窗口长度的选择会**反向决定**初值是否"保守"。

此外还有两个**外生约束**必须承认：

- **可观测性边界**：本仓库不持有子项目代码（Index.md 已知背景），所有 KPI 信号必须从**现有可观测事件流**派生，不能依赖"Amuro 自行声明完成"。
- **决策权不让渡**：KPI 阈值的最终拍板权在用户，a-execute / 后续 workshop 角色只能产出候选与依据，不能自行定阈值。

## 3. 梳理关键假设

按"是否可被当前信息证伪"分组：

### 可接受（被 WORKSHOP-001/002 隐式背书）

- **A1**：KPI 必须绑定 WORKSHOP-002 §8 已有收束信号占位，不引入新的事件类型。
- **A2**：MVP 方法与越界方法必须使用两套互不混淆的度量方向。
- **A3**：试运行（pilot）后允许重调 KPI 初值，本轮不要求最终稳定。
- **A4**：owner 行动率、主方法命中率等"软指标"存在合理观察窗口（周/月级），不应被压成单事件指标。

### 需在后续 workshop 显式确认

- **B1**（M4 PR 接受率分层假设）：当前占位 0.5 是"全量 PR"口径。WORKSHOP-001 三原则第一条"观测先于行动"暗示应当先按"非破坏性补丁 / 破坏性变更 / 纯文档"分层再聚合，否则 M4 的 0.5 没有语义。
- **B2**（M2 owner 行动率分母假设）：占位 0.3 的分母是"计划内 owner 数"，分子是"在观察窗口内产生可观察推进动作的 owner 数"。但"计划内 owner"如何枚举、子项目是否同步提供 owner 列表，尚无定论。
- **B3**（M6 链完成率的角色假设）：M6 是闭环方法（链完成率天然是"成功比例"），与 M1~M5 的"动作密度"型指标不在一个度量族。如果把 M6 列入主 KPI，会让 KPI 体系出现两类不同形态指标，可能需要拆成"主 KPI + 风险观察指标"两层。
- **B4**（V1~V3 越界审计的非 KPI 化假设）：本轮约束说"KPI 必须区分 MVP 推进与越界审计"。但 V 系列是否完全不设数值阈值、还是设"上限告警"（如月越界次数 > N 触发复审），尚无共识。

### 不可接受（违背 WORKSHOP-001 三原则或本轮约束）

- **C1**：让 Amuro 自报完成 → 直接违背"不接受 Amuro 自行判定完成"。
- **C2**：让 KPI 体系同时承担"激励推进"与"鼓励越界"两个方向 → 直接违背"区分 MVP 推进与越界审计"。
- **C3**：在本轮就把 KPI 初值当最终值、拒绝后续试运行调参 → 直接违背"初值必须保守、可在试运行后轮换"。

## 5. Goal LENS 视角结论

**目标已足够清晰到可以驱动 KPI 锁定 workshop，不需要再回头重定义"为什么要 KPI"**。当前真正缺的不是"目标是什么"，而是**目标被拆解到 KPI 层时的三项度量决策**：

1. **信号分层**：M4 PR 这类混合信号必须先按子类分层再聚合，不能直接用全量值。
2. **度量族分离**：M6 链完成率属"成功率"族，与 M1~M5 的"动作密度"族不同族，必须在 KPI 体系里分层（主 KPI vs 风险观察），不能混在同一阈值表。
3. **越界非 KPI 化**：V1~V3 必须用纯事件流 + 人工复审触发条件，不接受数值 KPI 化（否则会变相鼓励越界凑数）。

裁决建议（按 goal 视角的优先级）：

- **采纳**：A1~A4（已在 WORKSHOP-001/002 隐式背书），以及 B3（建议 M6 拆为风险观察层）、B4（建议 V 系列非 KPI 化）。
- **延后**：B1、B2 的具体聚合规则 / 枚举方式留到 TASK-006/007 解决，本轮先给"占位口径 + 已知未知"。
- **拒绝**：C1~C3（违背既有约束）。

**给下一轮（TASK-006 risk / TASK-007 norm）的接力棒**：

- risk LENS 必须回答"保守初值在不同方法上的安全边际"——即 0.3 / 0.5 这些占位值在风险视角下是否站得住。
- norm LENS 必须回答"KPI 体系的对外披露格式与审计可追溯性"——即 V 系列越界事件流如何被记录、复审、归档。
- actor LENS 必须在 KPI 锁定之后才进入，否则会出现"为没有 owner 的指标定指标"。

**Goal 视角最终判断**：本轮目标可推进，无须回头。核心风险不在目标本身，而在 KPI 层的三项度量决策（信号分层 / 度量族分离 / 越界非 KPI 化）若被绕过，会让整个 KPI 体系在第一个 pilot 月就失效。
