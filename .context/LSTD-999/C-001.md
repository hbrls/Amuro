## 1. 重述当前目标

**总项目目标（不变，继承自 `.context/LSTD-1234/Index.md`）**：

> Amuro 是一组并行的真实子项目的总项目。目标：**管理所有子项目的进展，并主动推动它们继续前进。用尽一切方法去推进项目，推进所有项目。**

**本轮聚焦（C-002 方法库枚举）**：

> 把 C-003 §5.1 给定的动作原语 `{只读观测, 提 issue, 留 comment, 提 PR, 发外部信号}` 组合成一份「Amuro 可立刻调用的推进方法清单」，并标注关系、指派主方法身份（对应 MR3 主方法身份）。

**Goal LENS 关注的元问题**：

- 这个目标本身**是否成立**？是否还需要修正表述？
- 目标的方向是否**可衡量**？"推进"如何被验证为真？
- 目标与"方法库枚举"这一本轮动作之间是否**对位**？枚举是否真能服务于"主动推进"？

## 5. Goal LENS 视角结论

### 5.1 先给判断（结论先行）

> **总目标成立且方向正确，但"推进"的定义未硬化。**
> **方法库枚举（C-002）是对的方向；本轮（C-002）最大风险不是"枚举不全"，而是"枚举完后没有可衡量的推进判定"。**
> **本轮应枚举 + 标注关系 + 暂定主方法；KPI 锁定 / 退出机制 / 优先级排序 推迟到 C-002 之后处理。**

### 5.2 主要理由

1. **总目标与三原则一致**："管理 + 主动推进"是清晰方向，与 WORKSHOP-001 "观测先于行动 / 方法库不锁定 / 每轮收束"无冲突。
2. **方法库是必要前置**：没有方法就没有"主动推进"的执行手段；"用尽一切方法"在语义上要求方法库存在。
3. **5 项原语覆盖了 MVP 所需的完整链路**：`只读观测 → 内部沟通（issue/comment）→ 内部贡献（PR）→ 外部信号`，没有遗漏关键分支。
4. **本轮是"工具箱搭建"，不是"工具使用"**：goal 视角下，工具箱本身的可衡量性弱于工具使用，但仍是"主动推进"的语义前提。
5. **异构性可被方法库吸收**：方法粒度保持在"原语组合"层面，不下沉到子项目定制，与 A4 一致。

### 5.3 反对意见 / 反例

- **O1（列举完备性焦虑）**：方法库枚举可能陷入"必须穷尽"的执念，违反"每轮收束"原则。  
  *回应*：C-002 必须以 MVP 收束，完备性留给后续轮迭代。
- **O2（goal 与 later LENS 冲突）**：goal 看"该不该做"，risk/execution 后续会校验"做不做得到"；若冲突，需在 later LENS 中显式回溯 goal。  
  *回应*：goal 是先验视角，被推翻概率低；若发生，按"三原则 → 重新 goal 澄清"流程处理。
- **O3（主方法指派过早锁定路径）**：违反"方法库不锁定"原则。  
  *回应*：主方法身份标注为"暂定 + 可轮换"，不在本轮固化。
- **O4（本轮越权承担 KPI 责任）**：KPI 锁定不在 C-002 范围，强行承担会破坏"一次一件事"原则。  
  *回应*：本轮只做"方法 × 收束信号"的占位符映射，KPI 数值推迟。
- **O5（外部信号越界）**："发外部信号"原语可能触发 L2/L3 授权，削弱 MVP 收束。  
  *回应*：本轮枚举时显式标记"越界 + 需授权"的方法，不阻塞 MVP 收束。

### 5.4 关键风险

| ID | 风险 | 缓解方向 |
|---|---|---|
| R1 | 方法与原语脱节（某方法被指派 > 4 个原语） | C-002 执行时硬性约束 + 越界标记 |
| R2 | 方法库无退出机制，失败方法持续占资源 | U5 推迟到 C-003 后处理，本轮不阻塞 |
| R3 | 主方法被错误锁定为"唯一推进手段" | 标注"暂定 + 可轮换"，留轮换窗口 |
| R4 | "推进"无可衡量定义 → 方法库变花名册 | U1 标记为"紧随 C-002 的高优先级未决项" |
| R5 | 子项目异构性导致方法跨项目推进力不均 | 允许"主方法 + 子项目特化变体"分层，但不破坏方法库整体性 |

### 5.5 明确裁决

| 议题 | 裁决 | 未选项 | 取舍依据 |
|---|---|---|---|
| 总目标是否修正 | **不修正** | 改为"管理 + 协作 / 治理 / 推进"等扩展表述 | 扩展表述模糊核心；WORKSHOP-001 已确认 |
| 方法库是否本轮做 | **本轮（C-002）必做** | 推迟到子项目成熟后再做 | MVP 试运行需要方法库存在 |
| 主方法是否本轮固化 | **暂定 + 标签化** | 完全不指派 / 完全固化 | 兼容"方法库不锁定"原则 |
| KPI 锁定是否本轮做 | **推迟到 C-003 之后** | 本轮就绑定数值 KPI | 避免"一次多事"；先有方法再有 KPI |
| 方法退出机制 | **推迟** | 本轮就设计下线流程 | 退出机制依赖 KPI，而 KPI 未锁定 |
| 子项目优先级 | **推迟** | 本轮排序 | 排序依赖 KPI 与方法 × 子项目矩阵 |
| 外部信号越界方法 | **显式标记 + 不阻塞 MVP** | 删除越界方法 | 保留未来 L2/L3 授权下的扩展空间 |

## 6. 收束声明

- Goal LENS 视角下，**C-002（方法库枚举）的目标层是清晰的、可推进的**。
- 本轮 C-002 执行时必须遵守的硬约束（来自 Goal LENS 裁决）：
  1. 每个方法必须可归约到 5 项原语之内，越界需显式标记。
  2. 每个方法必须给出至少 1 个「可观测的收束信号」（占位符即可，数值 KPI 推迟）。
  3. 主方法身份必须标注为"暂定 + 可轮换"，不固化。
  4. 方法之间必须显式标注关系（互斥 / 顺序 / 独立）。
- 本轮 C-001 输出**到此收束**。C-002 启动由 a-execute 工作流按"取任务 → 执行 → 删除 → 停止"流程调度。
