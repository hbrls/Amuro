## 1. 本轮目标与边界

### 1.1 目标

本轮回答四个问题：

1. 当前有界来源中有哪些语义单一的设备原始字段候选；
2. 每个候选应如何归入 `Identity`、`DeviceProfile` 或 `DeviceInfo`；
3. 当前证据是否支持其进入后续字段设计评估；
4. 还缺少哪些平台、实现、实际上报或价值证据。

本轮输出是调研框架、候选矩阵、证据边界和后续取证契约，不是最终客户端采集契约。

### 1.2 原始值边界

纳入候选的值必须满足：

- 由客户端、操作系统、平台 API 或厂商接口直接提供；
- 表达一个可以单独描述的设备事实；
- 不依赖拼接、哈希、阈值、扫描、历史窗口、规则、评分、模型或相似度计算；
- 能够追溯到具体来源条目，后续可使用平台、实现或实际上报证据验证。

客户端未经修改地转发某个 SDK 布尔值，不代表该值就是原始值。只要它来自 root、jailbreak、emulator、hook、tamper 等检测逻辑，就属于 `RiskSignal`，不进入三类原始字段。

### 1.3 非目标

- 不确定最终客户端采集字段清单或最终 `raw_payload` Schema；
- 不要求客户端在本轮立即新增字段；
- 不设计设备身份等价、主字段、备用字段、冲突字段或归并规则；
- 不设计 `device` / `user_device` 表、数据库键、唯一约束、索引、绑定或生命周期；
- 不讨论历史数据回填、处理结果审计或归并规则升级；
- 不设计 RiskSignal、检测方法、规则、评分、画像、模型或时间序列推导；
- 不改变 WORKSHOP-001 的 snapshot 方案和 WORKSHOP-002 的采集执行契约；
- 不讨论用户授权、PII 或合规限制。

## 2. 分类与研究状态标准

### 2.1 Identity

值由平台、系统或厂商直接提供，原始语义用于标识设备、系统安装、应用作用域主体、开发者作用域主体或广告主体。

归入 `Identity` 不代表该值稳定、唯一、永不重置或适合设备归并。标识对象、作用域、生成方、读取条件、重置方式、空值和生命周期都必须另行取证。

### 2.2 DeviceProfile

值直接描述设备硬件、操作系统或构建配置，主要在设备、系统或配置本身变化时改变。

`DeviceProfile` 只是原始属性分组，不是服务端画像，也不会因为相对稳定自动成为 `Identity`。

### 2.3 DeviceInfo

值是采集时刻直接读取的设备能力、当前状态、用户环境或连接环境事实，可以在设备不变时发生变化。

进入 `DeviceInfo` 不代表值得采集。高频变化、用户可修改、来源不可靠、语义重复或缺少独立用途都可能构成反对理由。

### 2.4 交叉处理顺序

1. 判断是否为直接原始值；不是则排除；
2. 判断原始语义是否用于标识；是则归 `Identity`；
3. 判断变化主要来自设备 / 系统配置，还是采集时刻环境；前者归 `DeviceProfile`，后者归 `DeviceInfo`；
4. 一个名称包含多个值语义时，能够无损拆分则拆分，不能界定则降级为待发现线索；
5. 每个进入矩阵的候选只能有一个主分类。

### 2.5 研究状态

| 状态 | 门槛 | 含义 |
| --- | --- | --- |
| Selected | 原始来源、字段语义、平台与值边界可核验；主要限制已知；有独立采集价值依据；关键反证已处理 | 可以进入后续字段设计评估，不表示最终采集 |
| NotSelected | 字段概念已明确，并有可审计的不选择理由 | 当前证据不支持进入后续设计，不表示永久无价值 |
| Undetermined | 字段概念已明确，但缺少决定性平台、实现、实际上报或价值证据 | 诚实保留未决，不得用常识或潜在算法用途强行升级 |

### 3.5 外部证据输入契约

每个新增来源至少记录：`source_id`、证据层、平台、标题、位置、版本或日期、访问方式、owner、状态、允许范围、能证明和不能证明的内容。

合法输入方式只有两种：

1. **任务级只读白名单**：明确列出允许读取的外部文件或 URL，限定只读、具体路径和当前用途；
2. **当前 Vision 内证据快照**：由来源 owner 提供带原始位置、版本、摘取范围和提供时间的可核验快照。

禁止：

- 因目录被提及就扫描整个外部 Vision；
- 使用 glob 扩大到未授权文件；
- 把模型记忆、聊天转述或无出处摘要当作证据；
- 把设计示例当作客户端实现或真实上报；
- 来源不可访问时凭常识补齐字段事实。

### 3.6 候选池覆盖完成条件

1. 来源清单已经冻结并标记版本或采集日期；
2. 行业候选、平台能力、客户端实现、项目实际上报四层均有来源或明确登记 missing；
3. 每个获准来源已经逐条检查，不采用抽样摘录；
4. 来源中的每个相关条目都映射为候选、别名、待发现线索或排除项；
5. 宽泛字段组已经拆成语义单一概念；
6. 跨来源同义字段已经归并，语义不同的同名字段已经拆分；
7. 每个候选至少具有来源引用和原始性初判；
8. 无法确认原始性或语义的条目不得静默删除；
9. 每个排除项都有来源和可复核理由；
10. 覆盖报告列明来源、候选、别名、线索、排除、Undetermined 和 Missing 数量。

完成上述条件只证明有界语料库覆盖完成，不证明开放世界不存在其他字段。

### 4.3 HH 与 AA

**HH：必须由人完成**

- 指定实际 owner；
- 批准外部只读白名单或提供受控快照；
- 证明客户端实现和 raw_payload 的版本、范围与真实性；
- 确认字段的独立采集价值；
- 对服务端观察 IP 是否重新纳入范围作最终裁决。

**AA：Agent 自主完成**

- 读取获准来源；
- 建立来源、候选、别名、线索和排除账本；
- 拆分宽泛名称并保留平台差异；
- 应用分类与研究状态门槛；
- 记录冲突、缺口、覆盖统计和回退状态；
- 在证据变化后更新本文件相关矩阵。

### 4.4 Agent 开始真实取证的条件

以下条件必须同时满足：

1. WORKSHOP owner 已选择白名单或证据快照方式；
2. 本轮授权明确列出允许读取的每个来源；
3. 每个来源具有平台、证据层、版本或日期和访问状态；
4. 客户端实现或 raw_payload 由对应 owner 确认；
5. 输出路径和本轮增量边界明确；
6. 未授权来源明确排除。

只有文件名猜测、聊天提及、抽象责任分配或方向性来源说明，不满足取证触发条件。

## 5. 候选规范化谱系

### 5.3 晋级门槛

## 10. 完整性、风险门禁与停止条件

### 10.1 不接受条件

2. 分类列包含“候选 / 待确认”，却计入已分类统计；

5. RiskSignal、服务端值或任务上下文进入候选矩阵；
6. Undetermined 没有字段级理由和补证需求；
7. 当前候选被描述为行业、平台或项目开放世界全集；
8. 人工执行请求预设某字段必须成为 Selected；
9. 排除项缺少来源或理由；
10. 结论依赖临时过程文件才能理解。

- 分类：`7 + 12 + 11 = 30`；
- 研究状态：`0 + 2 + 28 = 30`；
- 规范化：`38 - 9 + 1 = 30`；
- 开放占位符计入候选：0；
- 分类含“候选 / 待确认”：0；
- 无字段级理由的 Undetermined：0；
- D0 / D1 被描述为当前实现或实际上报：0；
- 候选矩阵中的 RiskSignal、服务端派生值或任务上下文：0；
- 待发现线索：15，全部不计入候选统计；
- 原子排除项：28，全部具有来源和理由；
- Missing 来源：8 类，全部披露影响和回退。

### 10.3 停止条件

本轮内部调研可以结束，因为：

- 三类原始字段的标准和交叉边界已经明确；

### 需要什么人工

请实际 owner 指定可使用的 GLNT-4 行业候选资料、iOS 官方资料和 Android 官方资料，并确认版本、范围和访问方式。

### 执行请求

- 提供 GLNT-4 允许读取的文件白名单，或在 GLNT-5 内提供带出处的受控证据快照；
- 为 iOS / Android 官方资料提供标题、URL 或快照、平台版本、访问日期和相关章节；
- 为每个来源填写证据层、平台、位置、版本 / 日期、owner、状态、允许范围、能证明和不能证明的内容；
- 不可提供的来源明确标为 missing，不得用二次转述或模型记忆代替。

### 完成判据

- 三类来源均有具体位置和元信息，或明确标为 missing；
- 允许范围可逐文件或逐证据单元核验；
- 资料足以检查字段名称、语义和平台限制；
- 结果回写到 `.context/GLNT-5/Index.md` 的“待澄清”段。

### 影响

- 阻塞主流程：否；阻塞候选池扩展到行业 / 平台证据层；
- 完成后下一步：按来源更新候选、线索和平台证据；
- 未完成时策略：维持当前 30 项有界候选，不声称开放世界覆盖。

## 9.4～9.5 提供当前 iOS / Android 客户端实现证据

> Target: iOS owner / Android owner / WORKSHOP owner

### 需要什么人工

请平台 owner 提供并确认当前版本真实读取设备字段的实现位置和处理链路。

### 执行请求

- 提供仓库版本或 commit、文件路径、读取入口、调用 API / 厂商接口和原始返回处理；
- 标明每个读取项对应的候选 ID，无法对应时提供具体值语义；
- 说明空值、占位值、权限、版本、厂商限制和失败处理；
- 确认材料代表当前实现，不是历史分支或示例代码。

### 完成判据

- iOS / Android 各自有可定位的版本与代码路径，或明确标为未实现 / missing；
- 每个读取项能映射到候选、别名、线索或排除项；
- 可以证明“当前代码尝试读取什么”，但不误写为生产一定上报；
- 结果回写到 `.context/GLNT-5/Index.md` 的“待澄清”段。

### 影响

- 阻塞主流程：否；阻塞“当前客户端已实现字段”结论；
- 完成后下一步：填充 I 层并与平台资料、真实上报对照；
- 未完成时策略：所有实现声明保持未知。

## 9.6～9.7 提供 iOS / Android 真实 raw_payload

> Target: 数据 owner / iOS owner / Android owner

### 需要什么人工

请数据 owner 提供能代表当前项目的 iOS / Android 脱敏原始上报样例，并确认样例范围与真实性。

### 执行请求

- 每个平台至少提供一组 `device_basic_snapshot.raw_payload` 原始样例；
- 提供客户端版本、系统版本、采集时间范围、样例数量、脱敏方式和数据 owner；
- 保留真实 key、类型、格式、单位、空值和占位值语义；
- 明确样例代表范围，不将单个样例泛化到全部版本或厂商。

### 完成判据

- iOS / Android 样例均有平台、版本、时间和 owner 元信息，或明确标为 missing；
- 每个 key 能映射到候选、别名、线索或排除项；
- 可以区分设计讨论、客户端读取和项目实际上报；
- 结果回写到 `.context/GLNT-5/Index.md` 的“待澄清”段。

### 影响

- 阻塞主流程：否；阻塞真实 key、类型、值形态和上报结论；
- 完成后下一步：填充 R 层并与 I 层对照；
- 未完成时策略：不得定义最终 raw_payload Schema 或称示例 key 已真实上报。

## 9.8 提供逐字段独立采集价值依据

> Target: 采集产品 owner / WORKSHOP owner / 数据使用方 owner

### 需要什么人工

请采集产品 owner 对每个候选提供独立采集价值、适用范围和反对理由，不以“可能用于风控”代替字段级依据。

### 执行请求

- 对 28 个 Undetermined 候选逐项说明直接用途、适用节点、消费主体和不采集影响；
- 同时说明高频变化、用户可修改、语义重复、可靠性、读取成本或缺少用途等反对理由；
- 明确证据来源和适用范围，允许结论为“不足以 Selected”；
- 不要求任何字段成为 Selected，不设计 RiskSignal；
- 电量和充电状态保持 NotSelected，除非以新价值依据重新开启研究。

### 完成判据

- 每个候选都有字段级用途与反对理由，或明确没有足够价值依据；
- 价值依据不依赖未定义算法、评分、画像或“行业都采集”；
- 可以与 P / I / R 证据共同重新评估研究状态；
- 结果回写到 `.context/GLNT-5/Index.md` 的“待澄清”段。

### 影响

- 阻塞主流程：否；阻塞任何候选晋级为 Selected；
- 完成后下一步：逐字段重新裁决研究状态；
- 未完成时策略：28 项继续保持 Undetermined。

## 7.1～7.15 明确待发现线索的直接值语义

> Target: iOS owner / Android owner / 来源文档 owner / 数据 owner

### 需要什么人工

请掌握平台、实现或真实数据的 owner 为 15 条线索提供具体字段定义和直接来源，或确认当前没有对应原始字段。

### 执行请求

- 按 L-001～L-015 提供名称、平台、值对象、直接来源、类型 / 格式和相邻概念边界；
- 对设备名称、产品名称、硬件代号、分辨率、密度、scale、语言、locale、时区、内存压力和网络接口地址明确单一值语义；
- 对 SDK 版本和 DST 状态证明其为运行时直接值，而不是编译上下文或客户端推导；
- 无法明确的线索继续保留，不得为增加候选数量强行晋级。

### 完成判据

- 每条线索获得可核验的单一值定义和直接来源，或明确保持未发现；
- 晋级项满足原始值边界并能分配唯一主分类；
- 未晋级项不进入候选和研究状态统计；
- 结果回写到 `.context/GLNT-5/Index.md` 的“待澄清”段。

### 影响

- 阻塞主流程：否；影响后续候选池完整性和统计；
- 完成后下一步：按新证据新增、拆分、合并或排除候选并重算统计；
- 未完成时策略：15 条线索保持不计数。
