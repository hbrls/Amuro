# Magii 初始化计划

## Requirements

本需求用于定义 Magii 项目的初始化目标、范围与验收标准。Magii 是一个具有自我学习和自我进化能力的智能调度与注册中心系统。

### Goals

- 完成 Magii 注册中心的核心功能搭建
- 建立调度能力的基础架构
- 实现自我学习与自我进化的核心机制
- 产出可运行的最小可用系统（MVP）

### Non-Goals

- 不包含具体业务功能（如爬虫、量化交易）的实现
- 不自建 Utils 类型能力，优先使用外部系统或 SaaS
- 不涉及大规模数据训练
- 不包含生产环境级别的优化

### Scope

- 注册中心（Registry）：服务注册、发现、调用关系管理
- 调度中心（Scheduler）：任务调度、工作流编排
- 自我学习模块：基于反馈的学习机制
- 自我进化模块：基于经验的优化与进化
- 核心数据库与 API

### Non-Scope

- 爬虫系统（外部）
- 量化交易系统（外部）
- UI 系统（外部或 SaaS）
- 具体业务逻辑实现
- 生产部署配置

### Functional Requirements

- **FR-001**: 系统应提供注册中心功能，能够注册和管理外部服务。
- **FR-002**: 系统应能够调度外部服务或任务。
- **FR-003**: 系统应记录服务调用关系和执行结果。
- **FR-004**: 系统应能够根据反馈数据进行自我调整。
- **FR-005**: 系统应记录学习过程并形成可追溯的经验。
- **FR-006**: 当系统遇到新场景时，应能够尝试不同的策略并评估效果。
- **FR-007**: 系统应提供 API 供外部调用或被外部系统调用。

### Success Metrics

| Metric           | Current | Target | How to Measure                      |
|------------------|---------|--------|-------------------------------------|
| 注册中心可用性   | 无     | 有    | 服务注册与发现功能正常               |
| 调度能力        | 无     | 有    | 任务调度功能可运行                   |
| 自我学习能力    | 无     | 有    | 功能可运行且产生学习结果             |
| 自我进化能力    | 无     | 有    | 系统能够基于反馈调整行为             |

### Dependencies

- **D-001**: 需要确定外部系统的接入方式（API/Webhook/SDK）
- **D-002**: 需要明确调度策略的具体场景

### Constraints

- **C-001**: Magii 保持紧凑，Utils 类型能力使用外部系统
- **C-002**: 初期采用轻量化实现
- **C-003**: 注册中心包含 App 和 Database

### Assumptions

- **A-001**: 项目将采用现代编程语言实现
- **A-002**: 外部系统通过 API 或 Webhook 对接
- **A-003**: 自我学习将从小规模场景开始验证
