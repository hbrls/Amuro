### 2.3 GAP #4 的 DO InterruptCoordinator 设计与 GAP #1/#2 的 JoinCoordinator 是否形成了清晰的共享/分立关系？

**是。** 关系清晰且已显式化：

| 维度 | JoinCoordinator (GAP #1/#2) | InterruptCoordinator (GAP #4) |
|------|---------------------------|-------------------------------|
| DO 职责 | 管理"多个子 Workflow 完成等待" | 管理"外部中断信号的接收与传播" |
| 核心接口 | register / reportDone / awaitAll / getResults | signal / check / acknowledge / registerInterests / getInterests / publishNonInterrupting / consumeNonInterrupting / cleanup / setTTL |
| 复用关系 | — | ❌ JoinCoordinator 不可直接复用于 GAP #4（语义正交） |
| 共享 | — | ✅ DO 作为状态存储的模式经验可迁移 |

C-016 §2.3 和 C-017 §4.6 均明确：两者是**并列分立**的 DO，共享 DO 使用模式经验（幂等、超时、生命周期管理），但接口和状态机设计迥异。

对后续 GAP 的复用展望（C-017 §4.8、§8.4）：
- **GAP #6**：非中断型 DO 检查模式可部分复用 InterruptCoordinator 的 publishNonInterrupting/consumeNonInterrupting
- **GAP #8**：InterruptCoordinator 预留了 `compensationRequired` 标记和 SagaCoordinator 接口，触达 GAP #8 的 Saga 编排器
