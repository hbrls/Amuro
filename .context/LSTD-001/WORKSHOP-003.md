## 关键发现

### GAP #12（历史查询）揭示的独特风险

C-035 对 #12 的分析发现了一项在其他高 GAP 中不存在的独特风险维度：

- **单次写入窗口的不可逆性**——实例完成后写入失败 = 永久数据丢失。运行时状态丢失可容忍，历史丢失不可逆，需 D1 事务 + 迁移失败补偿任务保障。
- **D1 历史表持续增长与查询性能退化**——若归档未及时就位，日完成量增长后 P0 查询可能退化到秒级。

### C-007 再评估发现的 5 项结构性遗漏

C-035 回检 C-007 的原始判定，识别出 5 项未覆盖的关键设计维度：

1. 历史写入的"单次窗口"——数据完整性风险
2. 历史表 schema 与运行时表的关系未设计
3. 变量快照粒度（实例级 vs 步骤级，存储量差 10-20 倍）未决策
4. R2 归档反向查询设计（热/温/冷三层架构）未展开
5. 审计合规保留期限与不可篡改需求未分析

### #11 与 #12 的耦合设计决策

pilot 判定 #11（运行时查询）与 #12（历史查询）应联合进行 plan-eng-review，理由：

- 共享同一 D1 schema 设计阶段——分离设计 = 后续必然返工
- 6/9 SP 与 #11 强耦合
- 联合产出 1.2-1.4× 而非 2× 瓶颈
- 联合 D1 schema（含运行时 + 历史表）已在 C-035 §4.1 定义清晰
